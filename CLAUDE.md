# Combust

Fuel-mileage tracker. One product, two independent clients on one backend:

- `web/` — React 19 + Vite + Tailwind v4 PWA (the **reference implementation**). See [web/CLAUDE.md](web/CLAUDE.md).
- `android/` — native Kotlin / Jetpack Compose app. See [android/CLAUDE.md](android/CLAUDE.md).
- `backend/` — hand-rolled PHP 8.1 + MySQL API, deployed to cPanel by zip upload ([CPANEL_SETUP.md](backend/CPANEL_SETUP.md)).
- Shared at the root: `DESIGN.md` (Ember design system), `PRODUCT.md`, `spec/` (data/sync contract + golden fixtures), `VERSION`, `CHANGELOG.md`.

## Two clients, one product — parity rules

- A new feature is built for **both** clients. If it ships in one first, say so in the PR and the CHANGELOG.
- Web is the reference: Android ports logic function-for-function (`web/src/lib/calculations.ts` →
  `android/core/.../Calculations.kt`, same names).
- The sync wire format is the contract: [spec/sync-format.md](spec/sync-format.md). Changing a persisted
  field means updating the spec, `backend/src/Controllers/SyncController.php`, web and Android together.
- Golden fixtures in `spec/fixtures/` are generated by the web code (`cd web && npm run gen:fixtures`).
  A web test fails when they are stale; the Android `:core` tests then fail until the Kotlin port matches.
- Design tokens come from `web/src/index.css` / `DESIGN.md`; Android mirrors them in `ui/theme`.

## Releasing

`VERSION` (repo root, e.g. `1.0.0`) is the single source of truth. Vite and Gradle read it;
`web/package.json` mirrors it (a test fails if they differ). Android `versionCode = major*10000 + minor*100 + patch`.
Tags are `vX.Y.Z`. Run the `/release X.Y.Z` skill: it bumps the version, writes the CHANGELOG entry,
builds/tests both clients and assembles `releases/vX.Y.Z/` (APK, web zip, backend zip, checksums, release notes).
It never commits, tags or pushes; afterwards: commit `release: X.Y.Z`, merge to `main`, tag, create the
GitHub Release with the artifacts and the CHANGELOG section as notes. Signing config lives in the
gitignored `android/keystore.properties`; never commit it, and always sign with the same keystore.

## Backend API (base URL `VITE_API_URL` / Android `BuildConfig.API_URL`)

JSON; errors `{error, details?}`. Auth: `Authorization: Bearer <jwt>` (HS256, 30 days, no refresh).
Public: `POST /auth/signup/send-otp`, `/auth/signup/verify`, `/auth/login`, `/auth/forgot-password/send-otp`,
`/auth/forgot-password/reset`. Authenticated: `GET /me`, `POST /sync`, `POST /account/reset-data`.
(Legacy REST `/vehicles`, `/entries` routes exist but neither client uses them.)

## Domain gotchas

- Mileage is measured full-fill to full-fill; it lands on the entry that *starts* the cycle. Partial fills
  add litres but have no mileage. Entries are ordered by odometer, not date.
- Mileage average is the plain mean of per-cycle mileages (not litre-weighted).
- No currency symbol is ever shown.
- The app is offline-first: local mode needs no account; signing in uploads local data and merges.
- Backend `.env` must exist or auth silently breaks; never commit it.
- Commit style: `feat:`, `fix:`, `chore:`, `docs:` with optional scope (`fix(android):`).
